## 二、它的结构逻辑

**按「功能维度」切课**：安装入门 → 高阶用法（模型/skill/连接器/手机）→ 办公提效 → 内容生产（公众号）→ 开发（小程序）→ 案例合集。

- 优点：**覆盖极全**，从装到高阶到多场景，一个会员能自学到底
- 本质：**个人自学工具课**，学员自己看、自己练、没人管

---

## 三、值得抄的四点

1. **Day0-Day7 的日更营结构（最值得抄）**
   Day0 装环境 → Day1 为什么做 → Day2 认识文件夹 → Day3 让它了解你 → Day4 素材卡 → Day5 成文 → Day6 发布 → Day7 回看闭环。
   **这是"从零到发出第一条成品"的完整动线**，每天一节、有连续性。可以直接变成我们 L2 的 30 天骨架，或单独做一个 7 天轻量引流营。
2. **"先让 WorkBuddy 了解你"（Day3）**
   这句命名很好——比"配置知识库"人性化。我们的 M1 装库可以借这个说法开场。
3. **"WorkBuddy + 场景"的命名法**
   《WorkBuddy + 办公提效：会议纪要自动…》——场景化命名，比"功能介绍"好卖。
4. **高阶清单要补进我们的附录**
   模型选择 / skill / 连接器 / 手机控制——这四块我们 L1 没教。**尤其"连接器"是 L3 定制（对接企业系统）的技术基础**，值得单独吃透。

---

## 四、它的四个死穴（我们的差异化所在）

| 死穴 | 说明 | 我们的打法 |
|---|---|---|
| **纯录播、无人盯** | 学完就忘，这是人性 | L2 陪跑 30 天专门解决"没人盯" |
| **面向个人，不面向企业** | 没有团队、岗位、客户数据、人效账本、老板视角 | 我们做企业内训，老板付费、员工使用、账本验收 |
| **按功能切，不按岗位任务切** | 学完知道有什么功能，不知道"我这岗位每天怎么用" | L1 四个动作：装库/派活/应答/复盘——按岗位任务切 |
| **无验收、无交付物** | 只有"待学习"进度条，学没学会不知道 | 四件套 + 结营上台验收 + 评分三栏 |

## 五、最狠的一招：把它变成我们的「课前预习教材」

**功能教学已经有人做全了，我们再讲安装、界面、模型选择就是重复劳动。**

做法：
1. 开课前把这套课（或同类免费教程）作为**预习清单**发给学员，要求课前看完"基础入门 + 高阶用法"
2. **L1 现场彻底"去功能化"**——不讲安装、不讲界面，只讲四个动作 + 做实操 + 验收
3. 预习没看懂的，现场有人答疑——**这正是内训相对录播的唯一价值：有人管、有人答、有人盯**

收益：讲师省下 2-3 小时讲功能的时间，全部换成实操；学员带着问题来，现场解决，产出更实。

---

## 六、结论

- **不是同一层竞争**：它是个人自学课（内容），我们是企业内训+陪跑+定制（服务）。
- **威胁在于**：老板会说"网上有课啊，为什么要花钱"——所以 L1 的卖点必须从"教功能"彻底转向**"带着你公司的真实资料，两天做出来你自己的东西，做完有人验收"**。
- **它帮了我们一个忙**：把"讲功能"这件苦活干了，我们可以专注在"陪着做出来"。
